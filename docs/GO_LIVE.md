# Go-live guide – Usman Electronics

_Last updated: 2026-10-24 · Keep this file up to date: every change that affects the server, `.env`, PHP or deployment is added here._

This is the full checklist for putting the site live **for the first time**, plus how to update it later.
Work through it top to bottom. Tick each box as you go.

| Needed | From | Used for |

## 1. Server requirements

- [ ] **PHP 8.2 or newer** (developed and tested on 8.2.12).
- [ ] **PHP extensions** – all must be enabled:
  `intl`, `gd` (with **WebP** support), `exif`, `pdo_mysql`, `mbstring`, `fileinfo`, `openssl`, `curl`, `ctype`, `tokenizer`, `xml`, `dom`, `bcmath`, `zip`
  - `intl` is required by the admin panel (Filament) – without it admin pages crash with *"The intl PHP extension is required"*.
  - `gd` + WebP is required to create the small image copies; `exif` straightens phone photos.
  - Check with: `php -m` (CLI) **and** a temporary `phpinfo()` page (web) – they can differ on shared hosting.
- [ ] **MySQL 8 / MariaDB 10.4+**, database charset `utf8mb4`, collation `utf8mb4_unicode_ci`.
- [ ] **Apache with `mod_rewrite`** (and ideally `mod_headers`). LiteSpeed works with the same `.htaccess`. Nginx needs its own config (ask before using Nginx).
- [ ] **Composer 2** on the server, or upload the `vendor/` folder built locally (see §4).
- [ ] **Cron jobs** available (cPanel → Cron Jobs). Needed for emails/WhatsApp, product imports/exports and nightly backups (§6).
- [ ] **`mysqldump`** available to PHP (it is on almost every host). Needed for the nightly database backup.
  If backups fail with "mysqldump not found", set `DB_DUMP_BINARY_PATH` to the folder that contains it (§5).
- [ ] **SSL certificate** (free AutoSSL / Let's Encrypt in cPanel).

## 2. php.ini settings (server)

Set in cPanel → *Select PHP Version → Options* / *MultiPHP INI Editor*, or in `php.ini` on a VPS.

| Setting | Value | Why |
|---|---|---|
| `upload_max_filesize` | `20M` | Admin uploads HD images up to 10 MB each |
| `post_max_size` | `25M` | Must be larger than `upload_max_filesize` |
| `memory_limit` | `512M` | Decoding big photos to make WebP copies (a 6000×4000 photo needs ~100 MB) |
| `max_execution_time` | `120` | Image processing on save |
| `max_input_time` | `120` | Slow uploads on mobile data |
| `expose_php` | `Off` | Don't reveal the PHP version |
| `display_errors` | `Off` | Never show errors to visitors |
| `extension=intl`, `extension=gd`, `extension=exif` | enabled | See §1 |

> Local XAMPP: `intl` and `gd` were enabled in `D:\xampp\php\php.ini` (backup: `php.ini.bak-before-intl-gd`). Restart Apache after php.ini changes.

## 3. Folder layout & document root

- [ ] Upload the project **outside** the public web folder, e.g. `/home/USER/usman-electronics/`.
- [ ] Point the domain's **document root to the `public/` folder**: `/home/USER/usman-electronics/public`
  (cPanel → Domains → Manage → Document Root). **Never** expose the project root (it contains `.env`).
  - If the host can't change the document root: ask support, or move to a host that can – don't put the whole project in `public_html`.
- [ ] Permissions: `storage/` and `bootstrap/cache/` writable by PHP (`775` folders, `664` files on most hosts).
- [ ] `storage/app/private/` must exist and be writable – customers' quote list files (photos/PDFs) are stored there
  privately (never reachable by URL; admins download them through `/admin/quotes/{id}/attachment`).

### `.htaccess` files (already in the repository – nothing to edit)
| File | Purpose |
|---|---|
| `public/.htaccess` | Laravel's standard rewrite rules (send everything to `index.php`, no directory listing) |
| `storage/app/public/.htaccess` | Uploaded files can't run as scripts (blocks `.php`, `.phtml`, `.svg`, `.js`, `.html` …) |

> `public/robots.txt` was **removed on purpose** – robots.txt is generated by the app (§9). Don't upload an old one.

## 4. Files to deploy

Deploy with Git (preferred) or upload a ZIP. **Do not upload:**
- [ ] `.env` from your computer (create a fresh one on the server, §5)
- [ ] `public/hot` – **important**: if this file exists on the server the site tries to load CSS/JS from `localhost:5173` and looks completely broken
  (it is created by `npm run dev` on your computer and left behind when the dev server stops – delete it before uploading; this also breaks the local site)
- [ ] `public/storage` (it's a link, created on the server), `storage/logs/*`, `node_modules/`, `.idea/`, `database/database.sqlite`

**Build assets** (`public/build` is not in Git):
- [ ] Either on the server: `npm ci && npm run build`
- [ ] Or locally: `npm run build`, then upload the `public/build/` folder.

**PHP dependencies:**
- [ ] On the server: `composer install --no-dev --optimize-autoloader`
- [ ] Or locally (same PHP version) and upload `vendor/`.

## 5. `.env` on the server

Copy `.env.example` to `.env` and set **every** value below. Then run `php artisan key:generate` (once – never change the key afterwards, it would make saved 2FA secrets unreadable).

```dotenv
APP_NAME="Usman Electronics"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://YOUR-DOMAIN.pk          # exact live URL, https, no trailing slash
                                        # (in a subfolder install it must include the folder, e.g. http://localhost/eelstore-clone/public – otherwise uploaded images 404)
APP_TIMEZONE=Asia/Karachi

LOG_LEVEL=warning

DB_CONNECTION=mysql
DB_HOST=localhost                        # from hosting panel
DB_PORT=3306
DB_DATABASE=...
DB_USERNAME=...
DB_PASSWORD=...

SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true               # cookies only over HTTPS
SESSION_ENCRYPT=true
QUEUE_CONNECTION=database
CACHE_STORE=database
QUEUE_WORKER_VIA_SCHEDULER=true          # false only if a Supervisor worker is set up (§6)

MAIL_MAILER=smtp
MAIL_HOST=...
MAIL_PORT=587                            # or 465
MAIL_SCHEME=null                         # "smtps" when using port 465
MAIL_USERNAME=...
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS="orders@YOUR-DOMAIN.pk"
MAIL_FROM_NAME="${APP_NAME}"

ORDER_ADMIN_EMAIL=owner@...              # receives every new order request

WHATSAPP_DRIVER=callmebot                # "log" until CallMeBot is set up
CALLMEBOT_PHONE=+923XXXXXXXXX
CALLMEBOT_API_KEY=...

TURNSTILE_SITE_KEY=                      # optional bot protection on checkout
TURNSTILE_SECRET_KEY=

ADMIN_REQUIRE_2FA=true                   # every admin must set up an authenticator app

ERROR_LOG_ENABLED=true                   # save errors to the database (Admin → Settings → Error log)
ERROR_LOG_RETENTION_DAYS=30              # errors not seen for this many days are deleted automatically
ERROR_LOG_HTTP_STATUSES=419,429          # also record "page expired" and rate limits (add 404 only to debug broken links)
ERROR_ALERT_EMAIL=                       # who gets "new error" emails (empty = ORDER_ADMIN_EMAIL)
ERROR_ALERTS_ENABLED=true

CSP_ENABLED=true                         # Content-Security-Policy header (violations go to the Error log)
CSP_REPORT_ONLY=false                    # true = report problems but block nothing (temporary troubleshooting only)

BACKUP_NOTIFY_EMAIL=                     # who gets "backup failed" emails (empty = ORDER_ADMIN_EMAIL)
BACKUP_ARCHIVE_PASSWORD=                 # recommended: password-protects backup zips (store it offline – needed to restore!)
BACKUP_MAX_MB=3000                       # oldest backups are deleted above this total size
DB_DUMP_BINARY_PATH=                     # only if mysqldump isn't found, e.g. /usr/bin
SEED_ADMIN_EMAIL=                        # leave EMPTY in production
SEED_ADMIN_PASSWORD=                     # leave EMPTY in production
```

## 6. First-time commands (run in this order, from the project folder)

```bash
composer install --no-dev --optimize-autoloader
php artisan key:generate                 # only the very first time
php artisan migrate --force              # creates all tables
php artisan db:seed --force              # OPTIONAL demo catalog – skip if you'll add real products yourself
php artisan storage:link                 # makes uploaded images visible at /storage
php artisan filament:assets              # admin panel CSS/JS into public/
php artisan app:create-admin             # first Owner account (asks name, email, strong password)
php artisan app:optimize-images          # WebP copies for any images already uploaded
php artisan app:launch-cleanup --dry-run # shows demo/test data that would be removed (see §8)
php artisan app:launch-cleanup           # removes it – pick sections, confirm
php artisan optimize                     # cache config, routes, views (run again after every .env change)
php artisan backup:run                   # first backup straight away (then nightly via cron)
```

- `storage:link` fails on some shared hosts (symlinks disabled): ask support to create
  `public/storage → ../storage/app/public`, or run `ln -s ../storage/app/public public/storage` inside `public/` via SSH/Terminal.

### Cron job (required – emails & WhatsApp alerts)
cPanel → Cron Jobs → "Once per minute":
```
* * * * * cd /home/USER/usman-electronics && php artisan schedule:run >> /dev/null 2>&1
```
(Use the full PHP path if needed, e.g. `/usr/local/bin/php` or `/opt/cpanel/ea-php82/root/usr/bin/php`.)
The scheduler:
- starts the queue worker every minute (order/quote emails, WhatsApp alerts, error alert emails, **product imports/exports**),
- makes a **backup** every night at 01:30 (cleanup at 01:00, health check at 03:00),
- daily removes failed jobs older than 30 days, activity-log entries older than a year and error-log entries not seen for 30 days.

**Without this cron line, emails and WhatsApp alerts are never sent, imports never finish and no backups are made.**

> VPS alternative: run `php artisan queue:work --tries=3` under Supervisor and set `QUEUE_WORKER_VIA_SCHEDULER=false` (still keep the cron line).

## 7. WhatsApp alerts (CallMeBot) – on the owner's phone

1. Follow https://www.callmebot.com/blog/free-api-whatsapp-messages/ : save the bot number listed there, send it
   *"I allow callmebot to send me messages"*.
2. Put the API key it replies with into `CALLMEBOT_API_KEY`, the owner's number into `CALLMEBOT_PHONE`, set `WHATSAPP_DRIVER=callmebot`.
3. `php artisan optimize`, then place a test order (§10).
- Later switch to the official WhatsApp Cloud API by setting `WHATSAPP_DRIVER=cloud_api` and the `WHATSAPP_CLOUD_*` values – no code changes.

## 8. Admin panel set-up after the first login (`https://YOUR-DOMAIN.pk/admin`)

- [ ] Log in with the account from `app:create-admin`, **set up 2FA** (Google Authenticator / Microsoft Authenticator) and **save the recovery codes**.
- [ ] Create a separate **Staff** account for each employee (Settings → Admin users). Never share the Owner login.
- [ ] Settings → Activity log shows who changed what (Owner only) – check it occasionally.
- [ ] Settings → **Error log** (Owner only): check it daily for the first week after launch; mark items resolved or clear them.
- [ ] **Website → Store & contact**: real phone, email, address, opening hours, social links, Google Maps *embed* code, contact-form recipient.
- [ ] **Website → Branding & theme**: logo, favicon, colours, optional placeholder image.
- [ ] **Website → Home page / Header & menu / Footer / Page texts / SEO**: review every text; choose which product blocks to show (deals, featured, brands, new arrivals).
- [ ] **Catalog → Brands**: upload brand logos (used in "Shop by brand" and on brand pages).
- [ ] **Website → Home slider**: upload real slides (about 1600 × 600 px).
- [ ] **Website → Content pages**: create at least *About us*, *Delivery & Cash on Delivery*, *Returns & warranty*, *Privacy policy*.
- [ ] **Catalog → Products → Import**: download the example CSV from the import window, fill it in Excel (one row per product;
  category and brand by name), save as **CSV**, upload. Import runs in the background (cron) – the bell icon shows the result,
  and failed rows can be downloaded with the reason. **Export** gives a CSV/Excel copy you can edit (e.g. prices) and import back.
- [ ] **Catalog**: real categories, brands and products with images. For wires/cables sold in several coil sizes, give every size
  the same **Size group** (e.g. `7/29 wire`) and a **Size label** (e.g. `90 m`) so they link to each other as "Other sizes";
  add a **Note for customers** where useful (e.g. "Custom lengths available – mention it in the order comment").

### Demo / test data to remove before launch
Run `php artisan app:launch-cleanup --dry-run` to see what's there, then `php artisan app:launch-cleanup` to remove it.
It handles: demo products/brands from the seeders (with images), test orders (e.g. **UE-100001**), test quote requests (with files),
contact messages, logs and queues, placeholder emails (`info@example.com`, `test@test.com`), the old "Laravel-powered clone" hero
text and slider rows whose image files don't exist. **Categories and admin users are kept.** Run it again after your own test orders (§10).

## 9. SEO after launch

- [ ] Check `https://YOUR-DOMAIN.pk/robots.txt` lists `Disallow: /admin` etc. and a `Sitemap:` line
  (it only does this when `APP_ENV=production`; otherwise it blocks everything – that's intended for test copies).
- [ ] Check `https://YOUR-DOMAIN.pk/sitemap.xml` lists products and categories (it refreshes every hour).
- [ ] Google Search Console: add the domain, verify (Website → SEO → verification code), submit `sitemap.xml`.
- [ ] Google Business Profile for the shop, linking to the website.

## 10. Smoke test after deploy

- [ ] Home, shop, a category page, a product page, contact page load over **https** with no errors.
- [ ] Images show (or the "No preview available" placeholder), no broken images.
- [ ] Add to cart → checkout → submit a test order with your own phone number:
  - thank-you page + "My Orders" show it,
  - **admin email arrives** (within ~1 minute – cron),
  - **WhatsApp alert arrives** on the owner's phone,
  - order appears in Admin → Order requests; "Mark contacted" changes the customer's status page.
- [ ] Contact form message arrives by email and in Admin → Contact messages.
- [ ] `/bulk-quote`: send a test quote with a photo attached → admin email (with the file attached) + WhatsApp alert arrive,
  it shows in Admin → Quote requests and "Download list" works. Delete it afterwards.
- [ ] Admin → Settings → Error log is reachable and (ideally) empty.
- [ ] Upload a product image in the admin → it shows on the site (WebP copy created).
- [ ] `https://YOUR-DOMAIN.pk/admin` requires login + 2FA.
- [ ] Response headers include `X-Frame-Options`, `X-Content-Type-Options`, `Strict-Transport-Security` (browser dev tools → Network).
- [ ] Search: try "2.5mm" and "2.5 mm" – both should find the same products.
- [ ] Admin dashboard shows the weekly charts; Settings → Backups lists the backup made in §6.
- [ ] Import 2–3 products from a CSV → bell icon reports success within ~1 minute (cron).
- [ ] Response headers also include `Content-Security-Policy`; after clicking around the site and admin,
  Settings → Error log shows **no "CSP violation"** entries.
- [ ] (If analytics IDs are set) GA4 Realtime / Meta Events Manager shows the visit and the test order as a lead.
- [ ] On a phone: open a mistyped URL (e.g. `/abc`) → branded "Page not found" page with search; submit checkout with a
  wrong phone number → the page jumps to the red, highlighted field.
- [ ] Remove the test orders/quotes: `php artisan app:launch-cleanup` (choose only those sections).

## 11. Backups & monitoring

- [ ] **Built-in backups**: every night the database + `storage/app/public` + `storage/app/private` are zipped into `storage/app/backups`
  (old ones removed automatically; "backup failed" emails go to `BACKUP_NOTIFY_EMAIL`). **Admin → Settings → Backups**: download one
  **every week** and keep it off the server (Google Drive / USB) – a backup on the same server doesn't help if the server is lost.
- [ ] Set `BACKUP_ARCHIVE_PASSWORD` and keep that password, the `.env` file and the `APP_KEY` somewhere safe offline – all three are needed to restore.
- [ ] Also enable the host's own daily backups if offered (belt and braces).
- [ ] Restore (if ever needed): unzip → import `db-dumps/*.sql` into MySQL → copy `public/` and `private/` back into `storage/app/` → `php artisan app:optimize-images`.
- [ ] Errors are saved in **Admin → Settings → Error log** (server crashes, failed emails/WhatsApp, expired pages, visitors' browser errors).
  `storage/logs/laravel.log` still has the raw details.

## 12. Updating the live site later

```bash
php artisan down --refresh=15            # maintenance page
git pull                                 # or upload the changed files
composer install --no-dev --optimize-autoloader
npm ci && npm run build                  # if CSS/JS/views changed (or upload public/build)
php artisan migrate --force
php artisan filament:assets
php artisan app:optimize-images          # only creates missing copies
php artisan optimize
php artisan queue:restart
php artisan up
```
